LDM Finance Website

Vehicle finance built for how New Zealand businesses actually operate.

Standalone finance-first site for LDM Motor Group, live at ldmfinance.co.nz — one application assessed across a multi-lender panel (UDC Finance, Marac, Avanti). Astro static build on Cloudflare Pages with live Motorcentral stock; the calculator and three-step application are the conversion surfaces.

Current phase Phase 3 · Content & sign-off
Next milestone Client sign-off: UDC wording + legal review Q3 2026

The Three Goals

📋
Qualified applications
Finance applications from tradies, SMEs and fleet managers nationwide — the #1 KPI surface is /apply.
🔍
Search + AI visibility
SEO/GEO/AEO ≥ 8/10 at the post-launch audit, Lighthouse mobile ≥ 85, LLM citation rate 15%+ by month 6.
🚚
Live stock, two CTAs
Every Motorcentral vehicle page shows an indicative weekly figure and exactly two next steps: calculate or apply.

Feed health endpoint — the daily stock check survives the gate
phase-2infrashipped/api/stock-status.jsonheroMissingfeed.source
Gating the site blinded the daily stock-feed check (5 Aug): it scraped `/vehicles/` for card counts, and every path started returning 401, which reads identically to an empty feed. Replaced the scrape with `/api/stock-status.json` — a build-time snapshot of feed provenance, vehicle counts, photo coverage and hero-image resolution, listed in `OPEN_PATHS` in the gate middleware so a monitor reads it without the preview password. Aggregate counts and vehicle titles only, `noindex` + `no-store`, exact-path match (a trailing slash still 401s). Two things make it better than the scrape it replaces: `photos.heroMissing` resolves heroes through the same `vehicleHero()` the cards call, so it cannot disagree with what renders — proven by breaking a photo set on purpose and watching it flip to `ok: false`; and `feed.source` is written by the ingest itself, so a silent fallback to the committed sample is visible instead of masquerading as fresh stock. PRs #23/#24

phase-2shipped39/39

Site gated for client review
phase-3infrashippedSITE_PASSWORD
Jack asked for the site to be password protected until the client has seen it, given the financial nature of the business and the outstanding legal sign-off. A Pages middleware puts everything behind HTTP Basic Auth when `SITE_PASSWORD` is set — pages, assets, API and robots.txt — with noindex/nofollow and no-store on every response so it cannot be indexed or cached. Deliberately fail-open: with the variable absent the site is public, so going live is deleting a variable rather than a code change. Verified both directions locally and on production (PR #21/#22). Note the site was publicly reachable 2–4 Aug, so a page or two may have been crawled before gating
