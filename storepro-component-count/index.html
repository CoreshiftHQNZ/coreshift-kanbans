Storepro Component Count

Drop a DWG, get back a Storepro-format BOM. Counting engine validated against a Storepro-confirmed job.

Reads Storepro's standardised dynamic-block DWGs directly: resolves anonymous dynamic blocks to their source components, reads bay strips + letters from the plan, levels/beam specs off the elevations, applies the Storepro rules (frames = bays + runs with shared-frame max-height, splice kits at 11,400 mm, back ties only where back-to-back frames align, protectors LH/RH by run end). On OPPAK-12515 (Glowbal NZ) the engine reproduced Storepro's confirmed component count line-for-line — 11/11 part-coded BOM lines — with every assumption surfaced as a clarification.

Current phase Phase 2 · Counting engine at oracle parity
Next milestone First live job through the staging UI then Storepro answers → lock the rule hypotheses

The Three Goals

📐
Eliminate the manual count
Today a Storepro designer prints the PDF and tallies every frame, beam, brace, mesh deck and protector by hand. We replace that with a job that runs in ~3 min and produces a matrix in the exact shape they already use.
⚖️
Catch ambiguity before the quote
DWG-block count + vision-derived recipe must agree. When they don't (e.g. designer copy-pasted a bay), the system surfaces a clarification rather than picking one silently.
📊
Matrix → quote, in one flow
End state: the Excel matches Storepro's Phase 1 Stage 2 sheet 1:1 — bay-type rows, component columns, totals row — ready to drop straight into Gareth + Gino's quoting workflow.
