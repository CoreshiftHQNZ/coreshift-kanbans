What “finished” means

Found by the gate closing, not by the gate failing. A module may not finish until the learner has run the thing they built — the rule that stops a module ending as a good conversation. P3TASK-027 → 0351 Aug

Doing real work ✓ — and the gate closed on the run it had been waiting for

merlin-module on the proven seven-beat anatomy (5–12 minutes, parallel step_hints, a recovery line per step) and merlin-loop’s five-step closure. Merlin guides; it never does the user’s work — it hands over a prompt for a fresh session and walks them through. Free-text reflection is reduced to change_tags + reflection_present on-device before anything is queued. Built 31 Jul, closed 1 Aug on the fifth gate run. That run was the missing one: a learner who built something, ran out of day, and came back next morning — the first module to span two sessions. She resumed with the exact phrase Merlin had planted the night before, wrote the prompt herself this time, and read the draft closely enough to notice it was chasing a signature she’d already got. She kept the prompt rather than sending the email. 3 to 4 on confidence, and her reason for the 3 had been “I’m not sure I could have written that block myself”. Two lessons outlived the phase. Handoffs: an instruction that names a file path gets read; one that names the skill gets run — and the single handoff that named a path is the only one that ever failed, across three runs, with its copy sitting in context. And authorship has to be declared: when the learner writes the prompt and Merlin tidies it into something reusable, saying “I’ve changed nothing” over two small additions is the one overstatement that undercuts what the module was for. Two things went further than the spec. The reflection vocabulary is closed, not just reduced, so an invented tag is refused rather than stored; and a reduction_ran flag separates “the reducer ran and found nothing” from “the reducer never ran”, which on the wire had been the same row — meaning a silently broken reducer would have looked exactly like a team doing unremarkable work.

P1TASK-011 · 01431 Jul

The shared adaptive engine block ✓

Three dials — pace, technical depth, expressiveness — as a shared instruction block every skill includes. Where reassurance lives got settled: it rides on pace, because depth exposes concepts and expressiveness governs how much someone opens up, and neither of those is about comfort. Warmth is the floor and never moves; reassurance is the dial. Stance transitions too: repeated struggle softens, impatience briskens, and anti-lock-in re-stances after one failed adjustment rather than two — two-to-trigger plus two-to-re-stance leaves someone stuck six turns, and a nervous learner has gone by four.

P1TASK-012 · 01331 Jul

Per-user memory + dial persistence ✓

profile.md, pathway.md, ledger.jsonl, outbox.jsonl, in two directories rather than one: recoverable state where auto-loading helps, the irreplaceable record where no consolidator walks. Each dial stores a value, a one-line reason and when it last moved — and the reason is held to a stricter test than surviving the next session: it has to survive being read by the person it is about. Write what someone did, never what they are.

P1TASK-01531 Jul

Append-only hashed ledger ✓

One judgement per line, hash-chained rather than hashed per line — because the realistic tamper is a deletion, which a per-line hash cannot see. Exempt from the memory consolidation pass by where it lives rather than by a code guard: anything in the memory directory is in reach of a pass we do not control.

P1TASK-017 · 017b31 Jul

P0TASK-01029 Jul

Phase 0 verification ✓ — all five properties hold

A forged token is refused, a learner token can’t read team rows, a prose payload is rejected, a duplicate event_id dedupes, and the outbox survives an offline flush. 36 vitest tests against the real deployed backend — mocks would pass equally well on a system that was wide open — plus 30 database-level assertions in tests/phase0-rls.sql, which covers what a test client cannot reach: the policies need a session with claims set, and a Merlin token is deliberately not a database credential. Two assertions worth keeping: one proves a rejection names the offending field but never quotes its contents; another reads back every stored event and proves no string contains a space.

P0TASK-00929 Jul

Sentry on Edge Functions only ✓

Never the MCP server — that runs on the learner’s machine, where a stack trace is an egress path the payload validator never inspects. defaultIntegrations: false is mandatory rather than tuning: the Deno SDK doesn’t instrument Deno.serve, so on a reused runtime one learner’s context can surface attached to another learner’s error. There is deliberately no captureException and no free-form message — the only entry point takes a closed set of enum fields, each checked against a safe pattern, so “never interpolate a rejected value” is a property of the code rather than a rule to remember. Pinned to sentry@8.55.0; the unpinned URL the spec suggested would resolve to whatever is latest at deploy time.

P0TASK-00829 Jul

Passive session telemetry ✓

The signal that separates “nobody is using this” from “eight of ten seats were active this week” — and it costs the learner nothing, because it never asks them anything. Shipped as .mjs rather than .sh: Merlin has to run on Windows, and Node is already required, which also lets the hook reuse the server’s event-id code instead of reimplementing the hash in shell. SessionStart does no network I/O at all — 52ms. Session duration is recorded via a per-session marker so duration_minutes reaches the utilisation metric. cwd is discarded outright; the session id is hashed into the event id and never transmitted.

P0TASK-00729 Jul

Local outbox + merlin_emit_event ✓

Disk first, network later: emit measured at ~40ms and returns before any request is made, so an unreachable backend is invisible to the learner. event_id = sha256(learner_id | type | natural_key) — a random UUID would make every retry a new row, so utilisation and ROI would drift upward on exactly the flaky connections where someone retries most, and nothing would look wrong. natural_key is hashed and discarded, never transmitted, which is what lets the session hook key on a session id without it becoming telemetry. Compaction renames rather than locks, so two concurrent sessions sharing one outbox is safe.

P0TASK-00629 Jul

Ingest + the payload allow-list ✓

No secret key on this path. It connects over the database URL, drops to the authenticated role and sets the claims from the verified token, so RLS enforces rather than an if in the handler. Privilege drops mid-transaction on purpose — the revocation check runs first, because that function isn’t executable by authenticated. The allow-list contains no bare string type: every string derives from the same pattern the database CHECK enforces, so nothing can pass validation and then fail in Postgres. A structural scan runs before schema validation and rejects reflection, evidence, expressiveness_read at any depth, so smuggled content produces a named, alertable rejection. Each row inserts in its own savepoint — without that, one poison event would abort every batch forever and silently end a learner’s telemetry.

P0TASK-00529 Jul

Bundled MCP server ✓

stdio, and fail-soft by contract: missing, expired, malformed and corrupt identity are all states it reports calmly, never exceptions it throws, because a broken tool panel makes Julie think she broke something. The token never reaches a tool result or stderr. The client decodes claims without verifying — it has no key, by design — so that gate is surface reduction for TASK-047, never the permission check.

P0TASK-00429 Jul

Server-issued identity that can’t be forged ✓

HS256 tokens signed with a key held only as a project secret, so the plugin can present an identity but never invent one. The key id is derived from the key material, so rotation needs no bookkeeping. One entry point does signature, claims and revocation together — a caller cannot skip the revocation check — and a registry outage fails closed rather than falling through to “valid”. Failures are enum codes; no rejected value ever reaches a log. The registry stores only the token id, never the token, so a dump of it grants nothing. Verified: self-elevation to owner, impersonation, business switching, alg:none and unknown-key are all refused.

P0TASK-00329 Jul

RLS default-deny on every table ✓

Seven tables, 14 policies, and anon holds zero grants anywhere — there is no unauthenticated surface. Team reads require the token to claim manager/owner and the live row to agree, so demoting someone takes effect on the next request rather than at token expiry, and a stale elevated token stops working immediately. business_id is derived from the learners table, never read from the token: a team-scoped read must never take a caller-supplied business, and a claimed one is still caller-supplied. A manager cannot read rubric-level judgement at all — that is exactly the “individual fumbles” they are never shown.

P0TASK-00229 Jul

Schema — with the no-prose rule as a constraint ✓

Six tables per the PRD, no messages table, and exactly one documented free-text column (nominations.label, present only after an explicit human decision to share). The privacy invariant is a CHECK constraint, not an ingest convention: every payload string must be space-free and under 128 characters, so a sentence cannot be stored at all — a whitelist rather than a length heuristic, because “reject strings over N chars” would still let too_slow_again through as smuggled sentiment. events is append-only by trigger (UPDATE and DELETE raise even for the secret key), event_id must be a hash so a later change can’t regress to random UUIDs, and business_id is stamped from the learner rather than trusted from the request.

P0TASK-001 · 001b29 Jul

Plugin bundle + repo front matter ✓

Manifest, MCP declaration and component dirs at the plugin root, named merlin to match the marketplace entry so install-by-name resolves. The README and .env.example both described the app-era product — naming egjpqixhwvvekjqldnyz as the database and Railway as the deploy target — which would have sent a coding agent to build the wrong thing against the wrong system. Both rewritten, with the two-Merlins distinction stated up front.

hardeningSCOPE-TOKEN-CHECK29 Jul

Revocation check moved out of the public API ✓

It started in the exposed schema so ingest could reach it over RPC with only the publishable key. A probe of the Edge runtime then showed SUPABASE_JWT_SECRET is absent — this project uses asymmetric signing keys — which forced the direct-connection route and made the RPC surface dead. Moved to the unexposed schema and dropped from public: an unauthenticated entry point into the auth system that no caller needs isn’t worth keeping for a route we aren’t taking.
