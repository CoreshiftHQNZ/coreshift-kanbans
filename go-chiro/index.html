Go-Chiro

Full NZ practice management system, built to replace Splose at a 1–5 person practice.

Reset 2026-08-18. An audit of the code against the live database found roughly 80% of the product built and none of it ever used — 0 invoices, 0 ACC claims, 2 completed sessions and 4 activated accounts, ever. The 3,816 appointments in the database are Splose history the sync pulled in, not work done here. So the bottleneck was never the build; it was that nobody ever ran a day on it, and five milestones were stacked on an unproven base. The app has been taken out of production, the Splose integration deleted (1,478 lines), and the milestones renumbered R1–R7 around one sentence: Luke runs a full clinic day in Go-Chiro with Splose closed. Full plan: docs/ROADMAP.md.

The Three Goals

📅
The diary the practice lives in
Day + week calendar, per-practitioner columns, venue and route-day aware, drag-to-reschedule with conflict detection. Splose's core job, replaced — and mobile-first, because the practice is.
🏥
Bill ACC without leaving the app
One-click Submit to ACC: a compliant invoice PDF emailed to providerinvoices@acc.co.nz with the ACC billing block, plus status tracking. This is what gates cutting the Splose cord.
🤖
The 1 → 3 staff jump
Recalls, waitlist, online intake, reminders and auto-pay do the admin a solo operator does by hand — so hires #2 and #3 are clinicians, not reception.

ACC contribution corrected to on-top, and set to $30
shippedR2moneyPR #120
The first version had the model backwards. ACC’s contribution is paid in addition to the fee, not deducted from it: the client pays the full $75 and ACC pays $30 as well, so practice revenue is $105. Shipped as a deduction, a $75 visit would have billed the client $45 and lost $30 a visit — caught while the amount was still 0, so it never ran. Fixed by adding the contribution as its own line item, which lifts the total and leaves patientPortion = total − accPortion equal to the fee. GST on the full $105 (1370c). $30 is now set on the ACC Appointment type in production, so the path is live rather than inert.

A failed payment can no longer un-pay a collected invoice
shippedR2moneyPR #117
payment_intent.payment_failed wrote status: "sent" with no check. Stripe redelivers and does not guarantee ordering, so a late or out-of-order failed event un-paid money already collected and re-presented the invoice to the patient. The guard now sits in the WHERE clause — status <> 'paid' and paid_at is null — so the check and the write are atomic; a read-then-write could still lose to a concurrent succeeded event. RETURNING makes a refused downgrade a logged warning rather than silence. Also stopped the success branch re-stamping paidAt on every redelivery. Verified by printing the compiled SQL and evaluating the predicate in Postgres across all six invoice states — read-only, nothing written.
ACC visits no longer draft at 100% to the patient
shippedR2moneyPR #116
Auto-drafts never set an ACC portion, so every ACC visit was drafted billing the patient the full fee. The split maths was always correct — the number did not exist anywhere, it lived in Luke’s head and was retyped per invoice. Now stored as appointment_types.acc_contribution_cents, beside price_cents, because ACC pays a fixed amount per service. Applies only when the type is ACC-eligible, a contribution is configured, and the patient has a live claim — billing ACC for a private visit is worse than the reverse. Clamped to the total. Verified against the shipped functions over six cases including the clamp and a negative input; GST stays on the full fee at 717c on 5500c. Migration 0030 applied by hand to both databases first.
