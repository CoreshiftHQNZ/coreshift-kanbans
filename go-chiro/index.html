Backlog · Tier 3 polish
7
T3BOOK-ADDR

Booking address autocomplete + early validation

Route-visit address is free-text with no autocomplete — easy to mistype and land in the wrong zone. Validate at step 2 instead of failing on the confirm POST. Google Places (geocoding service already exists server-side) would tighten this.

T3EX-VIDEO

Exercise video upload UI

Backend schema supports videoUrl + thumbnailUrl; ExercisesPage has the videoFile state but no upload control. Big lever for patient adherence — show the movement, don’t just describe it.

T3SCHED-CONFLICT

Schedule config — overlap detection + per-block errors

Booking config accepts overlapping blocks (e.g. 9–12 HQ + 11–13 route same day) and a save failure shows a generic error with no indication which day/block broke. Add conflict warnings + field-level validation.

T3ACC-PREFILL

ACC claim pre-fill from latest note

Diagnosis field hints “leave blank to pull from latest session note” but never auto-fills; provider number loads but doesn’t populate the input. Pre-fill both on patient select.

T3PDF-EXPORT

PDF/export for invoices & notes + add-to-calendar

Patients can’t download an invoice or session summary, and appointments have no iCal/Google calendar export. Common expectations for a health portal.

T3INVITE-STATE

Persist invite / read state

Practitioner “Invited” badge and patient note unread-dots are client-only state that resets on reload. Persist invite status + note read receipts to the backend.

T3NOTE-MD

Richer note rendering

Patient summary markdown parser only handles **bold** — headers, lists, links render as raw text. Use a proper minimal markdown renderer.

Up Next · Tier 2
5
T2CANCEL-RESCHED

Patient cancel / reschedule

Patients can only confirm — any change means phoning the practice, pushing load back on the practitioner. The #1 expectation of a booking portal. Needs cancel + reschedule flows + Splose write-back.

T2PATIENT-SETTINGS

Patient account / settings page

No way to update address, phone, email, notification prefs, or manage saved cards. Preference columns already exist in the DB — this is a UI build. Address especially matters: it drives route-visit zone assignment.

T2PRAC-REPLY

Practitioner can reply to client messages

Inbox is read-only — practitioner sees client messages and marks read but can’t reply. The patient side already has a full thread UI; close the loop.

T2PRAC-RESCHED

Reschedule / edit appointment from dashboard

Practitioner must drop into Splose to move an appointment. Quick moves are the common case — add inline reschedule on the dashboard.

T2HW-HISTORY

Homework history + real streak logic

Patients only see the latest assignment; completed historical homework is hidden. And the “streak” is just today’s done-count, not a rolling streak — misleading. Add history view + persisted streak.
