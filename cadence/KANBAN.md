## ✅ Done

- **📐 M1 — the idea, pressure-tested and reframed before a line of code** `M1` `planning` `shipped` — Ran the full ideation workflow. **Verdict: Strong, 25/30** — but the framing had to change to get there. The brief was "end-to-end GST filing"; validation established that **Xero NZ already computes the GST return and already files it to IRD**, so building that would rebuild something Colab gets free. The labour is everything that must be true *before* anyone presses the button — miscoded lines, wrong tax rates, unreconciled bank items, period-boundary strays, unexplained movement, records the client hasn't sent — and because the Google Sheet holding that checklist proves nothing, **the reviewer re-derives every return from scratch. Colab pays for the review twice.** So the product is the exception sweep + traceable workpaper + named sign-off, and filing is a feature on the end. **Three fatal flaws ranked with fast tests**, the sharpest being that the core assumption is still unverified: if the hours actually go into chasing clients rather than checking coding, the engine automates the cheap half and headcount doesn't move — which is why M2 and M3 contain no software. **Competition mapped honestly**, including the one that matters: Xero's own rebuilt Workpapers with a GST worksheet landing this year, bundled, from a vendor with far more resource than us. Six documents written: `product-idea.md`, `validation-report.md`, `VISION.md` (validated field-by-field against the skill's template by script), `product-vision.md`, `prd.md` (10 tables, 4 database-level integrity triggers, 22 endpoints, 25 functional requirements, 8 open questions each with a recommendation), and `product-roadmap.md`. **Two premises are labelled unverified throughout rather than quietly assumed:** the GST101A box map is *not* implemented from memory — it gets verified against IRD's live form first — and the 11-rule exception catalogue is explicitly a **hypothesis** to be rewritten from Colab's actual sheet in M2.

- **🗄️ The feasibility spike, harvested and archived** `M1` `decision` `shipped` — `core-ricky/cadence` was **a prototype built to prove a function was possible, not a foundation** — 43 commits in one week (2026-06-15 → 06-22), then dormant two months. It read like a shipped product (multi-tenant schema + RLS, a V1 dashboard with Prep → review attention → Run for real, team invites, the truth-sync reconcile loop, bulk post-back) and was initially planned as the thing GST would extend. Ricky's correction — it was a muck-around — changed the call, and **the clean rebuild is strictly better than the merge would have been.** A fresh Supabase project deletes the entire coupling problem at once: the additive-only migration constraint, the `verify-scope.ts` CI guard, the shared-schema review burden, **and** the single-use-Xero-refresh-token race between two services reading one token table. Nothing runs in parallel, so there's no half-finished port to strand. Renamed to **`cadence-spike`** and archived read-only, with a superseded banner pointing here; the *name* Cadence was kept for the product because a good name shouldn't go in the bin with the code. **Harvested as knowledge, not code:** the confidence rule (`consistent` / `conflicted` / `rare`), the payee-key normalisation, the proven result (8 of 26 lines auto-reconciled correctly, Woolworths/Kmart correctly deferred as conflicted), the schema shape as reference, and the operational lessons — truth-sync, the progress watchdog, payee grouping, Railway's `npm ci` optional-dep failure, the middleware relative-`Location` 500. **🔴 One honest cost of the clean break:** the exception engine's baseline was going to be the spike's live `coding_profiles`. It doesn't exist on a fresh build, so **the profile engine is now in scope as its own milestone (M5)** — previously assumed free. It's a fraction of the spike's scope, though: GST needs the *profile learning*, not the reconcile-and-auto-post machinery.

## 🅿️ Parking Lot

- **Bank reconciliation auto-posting** `parked` — The spike's whole function, and *not* needed for GST. GST needs the learned coding profile as a baseline; it does not need proposals, auto-posting or the reconcile loop. Real value and a plausible second module later — but carrying it now would double the build for no GST benefit. The spike proved it works (8/26 auto-reconciled correctly); that knowledge is banked.
- **Billing / Stripe** `parked` — The spike anticipated it; this product explicitly doesn't. The retainer is invoiced directly, so there are no payment rails, no billing UI and no PCI surface. Revisit only if Cadence is ever sold self-serve to multiple practices.
- **Client chase portal** `parked` `contingent` — Chasing clients for missing records may be a real share of the cycle. **If M2's timing shows chasing dominates, this stops being parked and becomes the pivot** — a different, cheaper product than the one currently planned.
- **Writing corrections back into Xero** `parked` — The preparer's natural next action after seeing a miscoded line, and bouncing to Xero is real friction. Deferred because writing to a client's ledger is the highest-consequence action available and needs trust the product hasn't earned. Reconsider after M8, behind explicit per-action confirmation.
- **Complex-basis and adjustment-heavy clients** `parked` `scope` — Payments and hybrid basis, private-use and entertainment adjustments, imported goods, zero-rated land, secondhand goods, bad debts, GST103 provisional-tax coupling. Each is a distinct ruleset. Declined **by design and in writing** rather than discovered as failures mid-cycle — which Coreshift can only do because it owns the asset. Unlock per category, ranked by how many client files each actually serves.
- **Multi-practice tenancy and self-serve onboarding** `parked` — `firm_id` is present throughout from the start, so this is small later; designing for practices we haven't met is speculative now.
- **CSV / data export** `parked` `security` — `gst_transactions` holds a client's complete financial detail, so an export path is a disclosure path. The workpaper PDF is the only artefact that leaves the system. Only on explicit request, with an access-controlled design.
- **Automated filing without a human signature** `never` — Not a scheduling decision. A named reviewer signs every return, always; filing something nobody looked at inverts the product's entire liability profile.
